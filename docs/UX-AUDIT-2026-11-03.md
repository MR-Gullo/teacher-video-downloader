# LessonShelf teacher UX audit, 3 November 2026

The ready popup already fits the task. A teacher can recognize a video, choose **Download video**, and leave both settings panels closed. The two biggest breaks occur when the companion cannot connect and when a video has already been saved.

## What was reviewed

- **Installed Zen preview.** The dark popup for *Mudflats Living* showed 28:32, a truncated repeated title, “Saved. English captions unavailable.” and **Show in Finder** below an orange **Download video**. This was an existing saved job. The capture did not start a download or activate Finder.
- **Browser fixture.** The current popup ran with simulated extension APIs. The light ready view, open settings, 42% download, failure, Downloads, missing companion, tool check, invalid link and dark theme show actual layout with synthetic data. They do not verify native jobs or permissions.
- **Public setup.** The signed-out GitHub guide at `94f9dcb` sends teachers through Homebrew, a source ZIP and Python. It describes **Find media**, **Download selected** and **Dependency check**. The local guide at `a1e32f4` names the new controls but still requires Terminal. Local `index.html` also teaches the old controls. The public guide and current popup describe different versions. [Guide as captured](https://github.com/MR-Gullo/teacher-video-downloader/blob/94f9dcb/docs/MAC-SETUP.md)
- **Source inspection.** Popup and companion behavior below refers to `a1e32f4`. The separate installer prototype at `7bdeb58` adds an installer experiment and tests. It supplies no released teacher installer.

## Fix first

1. **Give setup failures a way forward where they appear.** In the missing-companion fixture, Downloads says to check Help & setup, which is on another view. In `popup.js`, the status check catches connection failures, so **Reconnect** can display “Reconnected” even when the host is unavailable. Return a checked connection result. Put **Check connection** in the error view. Distinguish denied permission, connection lost, and confirmed missing required tools. An unreachable host alone cannot establish that the companion is absent. Show “No downloads yet” only after a successful empty response.
2. **Keep each action attached to the video it names.** Opening Paste link with an empty field still permits downloading the current tab. While a request is pending, the selected player can change before its job is bound to the result. Make current video and pasted link explicit modes. Empty or invalid input disables download in paste mode. **Use current video** exits it and clears its error. Snapshot source, document, player and settings at submission. Never attach its progress or Finder action to another source when the request returns.
3. **Make the saved file the primary action.** On the real Zen capture the strongest action starts another download attempt. Promote **Show in Finder** to the existing primary slot after success. Display the same short warning in Downloads. Keep the original playable file available when an optional copy or captions fail. Preserve separate warnings when more than one applies. Put diagnostic details and full paths behind **Saved files**. When a file has moved, show its last folder and an honest missing-file message.
4. **Help teachers recognize the video before downloading.** The current card displays the tab title on one truncated line. The selected player's title does not update it, and pasted jobs can all become “Video”. Prefer the selected player's reliable title, then a matching page heading or video metadata, then the tab title. Collapse repeated title segments only when they match. Allow two lines and place site and duration underneath. In paste mode show a safe filename or host until a title is known. Hide the player picker in that mode. Keep the theme, paste and Downloads controls in their familiar positions.
5. **Give waiting, failures and warnings distinct actions.** The running fixture shows “Downloading…” and “Downloading (42%)” above one progress bar. Queued and retry-wait jobs also use the downloading button. The fixture queue shows backend labels such as “complete warning”. Use a single job-state formatter for the popup and Downloads. Separate a timed retry from a failure that needs teacher action. When a caption check only establishes that captions were not saved, say “English captions weren't saved.” A rate limit or failed fetch does not prove that captions do not exist.
6. **Keep the queue operable with a keyboard.** Polling skips the entire list while a control inside it has focus. This protects focus but can leave an obsolete control on screen. Update rows by job ID and preserve focus, expanded file details and scroll. Move focus to the Downloads heading when opening it and return focus to **Downloads** on Back. Link errors to their field. Make each summary a full-width keyboard and pointer target. The fixture's portrait hint repeats “720p” even when 1080p or Best is selected. Use “For portrait video, the limit applies to width.” Show this only for a capped video setting. Disable irrelevant copy and resolution controls for audio-only output.

## Proposed popup behavior

Keep the light default, persistent dark toggle, **Paste link**, **Downloads**, and two closed sections. Keep the primary action in one place below the source. Use one nearby status line and at most one progress bar.

| State | Primary action or status | Supporting text or recovery |
| --- | --- | --- |
| Ready | Download video | Recognizable title, site, duration when known. |
| Permission needed | Allow and download | “Allow LessonShelf to send this video's title and links to the downloader on this Mac.” On denial, keep the source and allow another explicit attempt. |
| Preparing or queued | Finding video… / Waiting to download | Disable repeat submission. Omit a percentage. |
| Running or processing | Downloading, 42% / Saving file… | Use a measured percentage only during a measurable transfer. Show an indeterminate bar for an active phase with no estimate. |
| Waiting for automatic retry | Waiting to retry | No percentage. Keep Pause and Cancel in Downloads. |
| Paused or recoverable failure | Resume download / Retry download | Give one specific reason. An expired link needs a fresh source. For a rate limit, say “The site asked us to wait. Try again later.” Avoid offering an immediate repeat for a protected or denied source. |
| Saved | Show in Finder | “Saved”, “Saved without sound”, or “Saved. English captions weren't saved.” Combine applicable warnings. |
| Browser original | Download original file | Show “Original quality. Saved by your browser.” Route teachers to browser downloads for progress. Allow this direct-file path without companion consent. |

## Mac setup handoff

**Today.** Show “Mac installer isn't available for this preview.” Keep **Check connection** for teachers whose school already installed the companion. Offer an explicitly labelled manual guide for school IT. Include the installed extension version and use a bundled or version-matched guide. Keep the signed 0.2.1 release and temporary 0.3.0 preview distinct.

**When a compatible teacher release exists.** Offer **Get Mac companion** only for a verified release that matches this extension and Mac. The button downloads the versioned installer artifact. Tell the teacher to open it in Downloads, complete the macOS prompts, reopen LessonShelf and choose **Check connection**. Report “Ready to download” only after the native handshake and required tool checks succeed. Restore the intended video if it still matches. The teacher starts the download. Keep the browser from silently starting an installation or resubmitting a job. An existing installation with active work needs a supported update path.

## Acceptance checks

- In Zen, open two distinct players, navigate the source tab mid-resolution, switch to an empty pasted link and return. Confirm the title, job, status, retry and Finder action always belong to the chosen source.
- Exercise denied consent, missing host, missing required tool, absent optional engine, successful reconnect and disconnected Downloads. A missing optional engine must allow a supported fallback. A failed reconnect must never report success.
- Check queued, measured, unmeasured, retry-wait, paused, processing, failed and saved jobs. Show the same plain-language status in both views. Verify a confirmed silent source, missing captions and a combined warning. Check Finder with an existing and a moved file.
- Use Tab, Enter, Space and Back in the installed popup. Keep focus during polling and after view changes. Test narrow width, 200% text, light/dark and long titles. The normal primary action should be visible without scrolling at the default size. At larger text sizes allow vertical scrolling without clipping controls.
- Start at the **installed** Help link and the public landing page. Follow every step using its visible label. When the installer is available, repeat on a clean supported Mac without Terminal, verifying the downloaded artifact, user approval, reconnect and one completed test download. Until then, keep this acceptance check open.

The fresh capture set does not establish preparing, unknown-progress, silent-video, native select-menu, keyboard, Finder or clean-machine installation behavior. The installed settings disclosure did not visibly open during capture. A successful fixture disclosure does not resolve that Zen question. Review materials contain private browser information and stay outside the repository history.
