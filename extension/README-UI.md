# LessonShelf extension

`manifest.json` is the Chrome MV3 build. For Firefox, copy this directory to a separate folder and replace its `manifest.json` with `manifest.firefox.json`; Firefox ID: `teacher-video-downloader@local.invalid`. No bundler, CDN assets, remote scripts or telemetry.

The popup and full dashboard share `popup.html`. The extension only sends explicitly initiated commands to native host `org.teacher.video_downloader`; selecting checkboxes does not start downloads. Tabs and detected media are bounded locally, and removed when the tab closes/navigates. Stream detection requires an explicit site permission grant. A site permission does not grant all CDN domains; paste a discovered manifest when cross-origin requests are unavailable. Detection is limited to obvious media filename extensions and DOM media sources, not all possible players.

Cookies, browser profiles and arbitrary headers are never exported. URLs can contain signed tokens and are passed only to the companion and chosen download engine; private candidate URLs stay in extension local storage until tab cleanup. Do not publish your browser state or companion job database. UI displays URL host/path without query strings.

Validation: `node tests/ui-unit.cjs` exercises logic with a DOM shim. `node tests/ui-smoke.cjs` is a Playwright test that first loads the real unpacked extension and checks missing native-host UI, then injects a synthetic browser API fixture to exercise queue/selection/controls without downloading. Test fixture calls are clearly separate from actual native messaging integration. On this VM Chromium launch was blocked by local socket sandbox restrictions; escalated launch failed before running with a read-only mount error. Therefore browser rendering, screenshots and live extension/native integration are NOT claimed as passed. Run the script on a suitable test machine (requires Playwright and Chromium; adjust executablePath for the machine).

Additional supported-browser attempt: CUA confirmed a Linux VM Chromium session, but its URL policy rejected `file://` and `chrome://extensions/`; the approved HTTP fixture URL returned `ERR_CONNECTION_REFUSED` because the shell server and cloud browser did not share a reachable loopback namespace. No attempt was made to bypass those restrictions. `tests/ui-fixture-browser.cjs` is supplied for a later authorized local test environment; it serves the synthetic UI and browser in one process context. Its native responses are mocks, not evidence of successful downloads. The verified unit suite currently reports 14 assertions. No screenshots were produced in the blocked VM browser session.
